# 客户端 0.2.3-rc.1 复验候选版

针对 0.2.2 报告修复客户端路径快照校验、确认开关误判、multipart 重复 Content-Type、空间全失败仍成功、相册 feed 整数 ID、schema 提示与单频道周期参数，并完善下载前缀校验、Windows 临时文件清理和字段文档。

逐项结论见 [验收处置表](acceptance-remediation-0.2.3-rc.1.md)。本版不是正式发布批准：V28 审阅 N001999 尚需失败设备日志定位；V3 Compose env_save 仍是服务端缺陷。未修改 NAS/OAuth 服务端，未清理报告中的既有对象。授权码继续使用当前会话隐藏输入，不另开终端。

## 验证边界

本地 229 项单元测试、4 项 CLI 测试通过，新增正向流程覆盖集合写入和直播导入，不把协议模拟计为 NAS 真机端到端验收。专辑、路径关联、合集图片、直播文件导入、本地种子和前缀下载已在报告 NAS 完成本轮正向抽样；远程 URL 片单及更多动作仍需复验。Windows 临时文件删除标记实现已加强，原生异常下载场景待团队复验。

macOS ARM64 与 Linux x64 为此前完成原生验证的平台；本轮产物的具体检查见 client-validation-0.2.3-rc.1.json。macOS x64 为 Rosetta 验证范围，Windows x64/ARM64、Linux ARM64 继续作为待原生验收产物。无签名/公证；SHA-256 只校验完整性。

## 优先复验

1. 专辑创建→读取完整快照→已看→替换→关联 paths→解除关联→解散；空路径和结构化 paths 快照必须原样回传。
2. 直播 file/url 片单导入→草稿→保存→删除；single 模式 auto_update:false、周期0。
3. 本地 torrent parse_upload/add_upload，以及合集200×200 PNG封面上传；缺少 NAS 联网开关的写入仍须拒绝。
4. 相册整数 feed_ids 删除；不可达目标 file space 必须非零退出。
5. 下载前缀正确/错误、Windows 中断下载与失败清理、旧目标保护。offset>0 须 overwrite:true，长度等于本地前缀；当前完整重传并比对，不节省带宽。
6. 审阅空项目删除、添加媒体仍需日志定位；若返回 N001999，不反复提交，也不直接修改数据库。

依赖集合未变，沿用 2026-10-19 审计快照，未声称重新获取最新漏洞数据库。保留 rsa 0.9.10 / RUSTSEC-2023-0071 公钥加密路径适用性说明及后续跟踪要求。
