# 0.3.9 六机型汇总处置

依据 2026-10-23 的 0.3.5 六机型修复项回归汇总，核对当前 0.3.8。用户确认无法补充响应证据后，未能复现的问题保留边界并跳过；没有把报告中的真机失败判为不存在。

| 项目 | 当前结论与处置 |
| --- | --- |
| D01 >8 MiB 下载 | 真机报告仍失败；当前范围校验已有 HTTP 200+精确 Content-Range 兼容，但缺少失败响应头与块长度，无法确认进一步根因。本版未修复，不放宽块长度、范围、总长度或强 ETag 校验。大文件下载仍待定位和六机复验。 |
| D02/D03/D05/D09/D11/D12/D16/D20 | 汇总确认既有修复有效；保留现有实现和回归测试。实际清空回收站未验收。 |
| D04 直播草稿 | 补入 deleted、stream_type、tvg_id、tvg_name 已知只读字段；草稿回传 is_fav 过滤，频道编辑的收藏功能保留。未知字段仍拒绝。 |
| D06/N3 大参数 | 确认通用 JSON 解析器仍限 1 MiB，与文件入口 16 MiB 不一致；统一为 16 MiB，新增超过 1 MiB 成功及超过 16 MiB 拒绝回归。 |
| D07/N2 mkdir | 0.3.6 已文档化固件差异：rename:0 不自动建副本，部分固件返回既有目录幂等成功。保留后端结果。 |
| D08/N5 占位 | 现为明确模板，需先通过 file space 获取真实路径，无需修改。 |
| D10 duplicates | 当前 schema 已声明 group_id、scan_id、file_ids；本版补充报告示例数字 ID 的直接参数回归，均可通过。缺少原始命令/错误细节，不能确认六机真机失败根因，跳过业务改动；清理链路仍待真机复验。 |
| D13 action 提示 | 已修复：基于枚举或明确白名单给出可用动作，不回显用户输入值。 |
| D14 应用未安装 | 当前已有明确状态与备用应用列表门禁。泛化 HTTP 400 不能可靠等同未安装；未补充证据，跳过扩大映射。 |
| D15 SMART SN | 不擅自去掉真实序列号中的连字符；使用磁盘列表的 sn 字段，勿用展示用 smart.serial_number。无法确认具体映射，跳过自动归一化。 |
| D17 选路可观测性 | 增强建议，当前未增加新命令；不代表 cloud 有 LAN 泄露证据。 |
| D18 保险箱 tips | 当前透传 NAS 返回的提示。无法证明 111111 不是用户设置值，不在客户端替换或伪造提示。 |
| D19 CPU | 服务端机型信息问题；客户端保持透传。 |
| N1 read 上限 | 确认静默 clamp，改为 max_bytes 超过 1048576 时 E_PARAM，提示分段读取或 file download。范围内仍返回 truncated/next_offset。 |
| N4 Compose | 列表响应错误现在提示检查 Docker/Compose 启用状态和账号权限，不把异常响应断言为一定未安装。 |

本版正式验收包为 0.3.9；包含上述已确认修复，但 D01、D10 仍有真机报告未闭环，不能表述为六机全通过。Windows stdin 的 0.3.8 修复也仍需原生验收。没有修改 NAS/OAuth 服务端，没有执行真实业务删除。
