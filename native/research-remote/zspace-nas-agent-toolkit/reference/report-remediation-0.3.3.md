# 四设备旧版回归报告处置（0.3.3）

核对对象为 Q4-9Y70、Z4Pro+-9JYG、Z4Pro-OKNG、Z425-BCRV 四份 2026-10-21/22 报告。报告测试的是 0.2.3 系列；以下结论来自对 0.3.2 源码的逐项核对及 0.3.3 自动测试，不把报告中的建议当作发布授权，也不把交叉构建当作真机业务验收。

| 报告 | 当前版确认结果 | 0.3.3 处置 |
| --- | --- | --- |
| Q4-9Y70 | 大文件范围响应、回收站端点/恢复路径、直播读写 schema、Compose 项目检查、命令行大 JSON、mkdir 自动改名仍存在 | 全部修复；新增 `--params-file`；真机闭环待复测 |
| Z4Pro+-9JYG | 直播 schema、回收站、Compose 仍存在；占位 profile 文档仍存在；OAuth/appstore 项为环境状态 | 修复客户端与当前文档；环境项不伪装修复 |
| Z4Pro-OKNG | 大文件、回收站、直播、Compose、BT 非 JSON 成功响应仍存在 | 修复协议与结果处理；真机闭环待复测 |
| Z425-BCRV | 大文件、直播可确认；回收站/Compose 在该设备受权限或前置限制，但已由其他报告交叉证实 | 按跨设备证据修复；该设备仍须具备权限/项目后复测 |

## 共同问题结论

- 已修复：精确范围分块、回收站列表与池级恢复路径、直播草稿字段过滤与默认空删除列表、Compose 目标存在性、BT 2xx 非 JSON、mkdir 默认冲突、较大 JSON 参数文件通道、当前文档 profile 占位。
- 当前版原已修复：`file duplicates group_files/clean` 参数契约、`media search query` 字段、主要命名工具未知字段校验，因此未重复改动。
- 保留既有明确语义：download offset 会完整重传并核对前缀，不宣称节省带宽；响应继续报告实际 `transferred_bytes`。
- 不判为客户端缺陷：设备 appstore 间歇 403、OAuth 失效、SMART SN 取值前置、未安装应用、账号无回收站权限、搜索索引延迟。
- 延后增强：脱敏选路诊断属于可观测性改进，不改变连接正确性，本版未增加新的潜在敏感输出。

所有 NAS 业务修复均需在四台报告设备上重新执行对应闭环。当前发布证据只能证明客户端单元/协议测试、六平台构建、CDN 完整性和包结构。
